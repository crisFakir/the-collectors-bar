# ADR-0003: Use PlantUML for UML diagrams

- **Status:** Proposed
- **Date:** 2026-10-28
- **Related requirements:** NFR-DOC-01

## Context

The documentation needs UML diagrams: use case, domain model (class), sequence and state diagrams. They must be:

- versioned with the code and reviewable in pull requests;
- viewable on GitHub and in JetBrains IDEs;
- proper UML, including use case diagrams (actors, use cases, system boundary, `<<include>>` / `<<extend>>`).

## Options considered

1. **StarUML / draw.io** — visual editors.
   - Pros: familiar, drag and drop.
   - Cons: binary or verbose files, unreadable diffs; images get out of sync with the source.
2. **Mermaid** — text diagrams rendered natively by GitHub.
   - Pros: no build step on GitHub.
   - Cons: no real use case diagram type; limited UML notation.
3. **PlantUML** — text diagrams with full UML support.
   - Pros: all UML diagram types, including use case; readable diffs; live preview in JetBrains IDEs (PlantUML Integration plugin).
   - Cons: GitHub does not render it inside Markdown, so an SVG must be generated.

## Decision

We will write UML diagrams in **PlantUML** (`docs/diagrams/*.puml`) and commit the generated **SVG** next to each source, embedding the SVG in the Markdown documents. A CI job will later regenerate the SVGs automatically. Mermaid may still be used for small, non-UML flowcharts inside Markdown.

## Consequences

- Diagrams are text, reviewed like code.
- Contributors need the PlantUML plugin (or Java + PlantUML) to preview locally.
- Until the CI job exists, SVGs must be regenerated by hand after editing a `.puml` file.
